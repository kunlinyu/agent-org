## 1. 阶段一：DSH 技术细节（24 项）

### A. 架构与组合

| 编号 | 标题 | 简单描述 | 状态 |
|---|---|---|---|
| T01 | 插件体系与 profile 组合 | DSH 的一切能力都是 Cordis 插件；profile 由若干 bundle 层加你自己的 patch 层拼成，行可被覆盖、插入、禁用 | ✓ 定稿见 [04](04-DSH插件体系术语备忘.md) |
| T02 | Agent 预设（preset） | 一个 preset 声明"这个 agent 挂哪些插件"，从而决定它的工具集、persona、模型档 | ☐ |
| T03 | 提示与上下文的注入面 | 系统提示分节注册、AGENTS.md 加载、skill 按需加载、运行时上下文（时间/身份）自动追加 | ☐ |

### B. 会话与事件

| 编号 | 标题 | 简单描述 | 状态 |
|---|---|---|---|
| T04 | 会话日志（事件溯源） | 每个会话是一条 append-only 事件日志，是唯一真相；"模型看得见"等价于"已记录在案" | ☐ |
| T05 | 投影（projection） | 从日志派生的"当前值"视图（子代理目录、待答问题、任务板等），可注册、可缓存、可订阅 | ☐ |
| T06 | 插件的 log-only 事件 | 插件能往会话日志写自定义事件，这类事件不进入模型上下文 | ☐ |

### C. 子代理（多 agent 核心）

| 编号 | 标题 | 简单描述 | 状态 |
|---|---|---|---|
| T07 | 单亲树与深度 | 每个 agent 只有一个创建者，形成一棵树；root 深度 0，`maxDepth=2` 即最多 3 层 | ☐ |
| T08 | spawn 与 fork | spawn 建全新上下文的子代理（可指定独立 preset）；fork 注入父已完成轮的历史并继承父的组合 | ☐ |
| T09 | 消息投递 | `send_message` 在同一棵树内全连通、可跨分支；运行中收到中途引导（Steer），空闲则被唤醒 | ☐ |
| T10 | 打断与"没有暂停" | 只有祖先或用户能打断子代理当前轮；没有暂停/恢复原语 | ☐ |
| T11 | 容量上限 | `maxActiveSubagents` 是**每棵树**内"驻留激活数"的上限，超限直接报错、不排队 | ☐ |
| T12 | 名字与目录 | 名字同父唯一、不可改、不可回收；父会话持有持久子代理目录（catalog） | ☐ |
| T13 | 结果投递与结构化输出 | 父只收到子的最终文本；可选 `outputSchema` 让子返回校验过的结构化结果 | ☐ |
| T14 | `list_agents` 的状态语义 | 只报 `running`/`inactive`，表示"引擎在不在跑"，不代表任务完成或成功 | ☐ |

### D. 协作与交互

| 编号 | 标题 | 简单描述 | 状态 |
|---|---|---|---|
| T15 | Agent Team 任务板 | 树内共享的持久任务板：认领、依赖 DAG、写域提示、CAS 版本、root 可改派 | ☐ |
| T16 | 结构化提问 | `ask_user_question` 提供选项/按钮式提问；**但 delegated 子代理调用会被直接拒绝** | ☐ |
| T17 | 审批与权限档 | 权限档与审批策略按会话生效；子代理的审批由"拥有它的 answerer"处理 | ☐ |
| T18 | 定时、后台任务、目标续跑 | `schedule` 定时投递（不能指向 delegated 子会话）、`jobs` 后台进程、`goal` 同会话自动续跑 | ☐ |

### E. 扩展面

| 编号 | 标题 | 简单描述 | 状态 |
|---|---|---|---|
| T19 | 工具注册与执行管线 | 工具注册进 `ctx.tools`，执行前后有 waterfall 钩子，可在执行前拒绝调用 | ☐ |
| T20 | 客户端 UI 插槽 | 前端按 slot 注册组件（侧边栏、会话区等），scope 分 root/session，类型分 single/list/keyed | ☐ |
| T21 | 存储与查询 | 插件自有 KV 域（`storageDomain`）、跨会话检索（SQLite FTS）、投影缓存、工作区注册表 | ☐ |
| T22 | 计量与观测 | token 计量（参考值非账单）、会话统计、OTel 遥测、`agent/*` 生命周期事件 | ☐ |
| T23 | worktree 与工作目录 | 实验性服务：建独立 git worktree 并把**调用者会话**的 cwd 切过去；受沙箱写策略约束 | ☐ |
| T24 | 沙箱与文件策略 | read-only / workspace-write / full 三档，由 ACL/令牌实现；凭据类与管道类操作在受限模式下会被拒 | ☐ |
